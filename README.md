# 中医名师 · 问诊采集

> **核心命题：患者说的第一句话，往往不能用。**
>
> 学术依据：倪海厦六经辨证 · 李可（扶阳 / 破格救心）

一个给 AI Agent 用的中医问诊技能（Skill）。它解决的不是"问得够不够多"，而是**问到了错误的东西**——患者开口给的是判断（"湿气重""肾虚""经络不通""上火"），辨证需要的却是可观察的事实（苔厚？便溏？膝冷？尿少？）。

本技能把"从口述到可用信息"的转换过程固化成一套可复用流程：**判定标准 → 分轮追问 → 标准输出**，辨证框架承倪海厦六经辨证与李可（扶阳 / 破格救心）两系。

## 一条命令安装

仓库根目录即技能本身，克隆时直接指定目标目录即可，**无需再复制**。下面这一行 macOS / Linux / Windows PowerShell 通用：

```bash
git clone https://github.com/zhouran0628/zy "$HOME/.workbuddy/skills/中医名师"
```

也可以只发这一句给 AI：

> 把 https://github.com/zhouran0628/zy 克隆到我的 ~/.workbuddy/skills/中医名师

装完目录长这样，`references/` 必须与 `SKILL.md` 同级：

```
~/.workbuddy/skills/中医名师/
├── SKILL.md
└── references/
    ├── question-bank.md
    └── dialogue-patterns.md
```

不想用 git 的话，下载 ZIP 解压后改名放进 `~/.workbuddy/skills/` 也可以。**目录名建议与 frontmatter 的 `name` 保持一致**，便于查找。

技能是纯 Markdown，无脚本、无网络请求、无依赖，安装不需要任何授权。

## 为什么需要它

真实的问诊失败，通常不是知识不够，而是两个失真源：

| 失真源 | 后果 | 本技能的对策 |
|---|---|---|
| **患者说的是结论，不是症状** | 顺着结论套方，方向一开始就错 | 铁律一：病机名词一律视为结论，必须还原成症状 |
| **一次问太多** | 十问换回十份模糊答案，等于没问 | 铁律二：每轮最多追问 2–3 项，上一轮答案决定下一轮 |

第三条是输出纪律：不问结论、不问诱导性问题，只问可观察事实。

---

## 触发方式

任一条命中即会被加载：

- 用户描述身体不适、需要判断（"我最近眼睛干、腿也不舒服"）
- 用户问"该问什么 / 怎么问病人"（"如何让患者口述问题"）
- 需要设计问诊表 / 问卷 / AI 问诊流程
- 信息零散，需要判断还缺什么（"这些信息够辨证了吗"）
- 用户给出的是病机名词而非症状（"我湿气重""我经络不通"）

### references/question-bank.md

按系统组织的追问库：寒热与汗、睡眠、饮食口味、大便、小便、头面五官、四肢躯体、精神体力、男科、女性、旧病与用药。每条都标注了**为什么问**与对应的辨证指向，另附可直接打印的 A4 患者自填表（13 题）和舌象三张拍摄规范。

### references/dialogue-patterns.md

完整记录了一次五轮追问：从"眼睛干 + 下肢经络不通"这句结论出发，逐轮剥出**膝冷 / 手足温 / 大便成形 / 口渴冷热不择 / 小便量少有残余感**，最后收敛到方剂层级。

**其中包含三次判断被推翻**——第 1 轮排除厥阴少阴、第 2 轮推翻"太阴病"、第 3 轮主方从苓桂术甘汤改为五苓散。这是刻意保留的：真实的问诊就是一路修正的，**这不是失败，这是问诊在工作**。

## 一条可自检的标准

> 如果问到第五轮还在一次抛十个问题，说明前面没收住。

比十条原则都管用。收敛的标志是**问题越问越少、越问越准**，而不是越问越多。

---

## 边界（重要）

- 本技能只做**信息采集与辨证框架**，不替代面诊，**不下诊断、不开处方、不给个人剂量**。
- AI 无法切脉；脉象只能接收自述或设备数据，不作独立依据。
- 危重情形一律先转就医，不做辨证分析。
- 涉及方剂、剂量（尤其附子、细辛等有毒药）须由执业中医师面诊后开具。

本仓库内容仅用于中医学习与学术研究。
